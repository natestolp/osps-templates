# OSPS Templates

This project provides simple, reusable security and governance policy templates for open source projects to help them document and communicate their security posture, practices, frameworks, and controls.

The goal is to take the guesswork out of documenting security practices. Projects can start with a simple template, copy and adapt it to their needs, link to practices they already have in place, and adopt recommended practices where gaps exist.

Templates may cover areas such as dependency management, security testing, vulnerability disclosure, secrets management, access control, and other practices referenced by the Open Source Project Security Baseline (OSPS) and related frameworks.

The project also helps projects identify where relevant security information should live and makes existing practices easier to discover and communicate. In some cases, the template may simply help a project document an existing practice or point contributors to resources such as secure development training.

## Quick Start

The easiest way to contribute is to:

* Review the available policy and security templates.
* Identify templates that could be useful to an open source project.
* Propose new templates for baseline requirements that reference policies, documents, or other long-form artifacts.
* Improve existing templates to make them easier to adopt and customize.
* Identify areas where projects may benefit from links to existing practices, frameworks, or training.
* File issues for missing templates, improvements, or additional use cases.

### Current Templates

The project currently includes templates for:

* Software Composition Analysis (Dependency) Policy
* Coordinated Vulnerability Disclosure (CVD) Policy
* Static Application Security Testing (SAST) Policy
* Test Coverage Policy for Major Changes
* Secrets and Credentials Management Policy
* Escalated Permissions Review Policy

## Scope and Areas of Interest

Areas currently under consideration include:

* Elements of the Open Source Project Security Baseline that reference a document, policy, or other long-form artifact, to identify where templates are needed.
* Cybersecurity policy requirements associated with the Cyber Resilience Act (CRA).
* Dependency management and software composition analysis.
* Security testing and secure development practices.
* Vulnerability disclosure and response.
* Secrets and credentials management.
* Access and permissions management.
* Documentation of existing security practices and controls.
